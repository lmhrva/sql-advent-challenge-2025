Query:
Some elves took time off after the holiday rush, but not everyone has returned to work. List all elves by name, showing their return date. If they have not returned from vacation, list their return date as "Still resting".

Tables
elves(elf_id, elf_name)
vacations(elf_id, start_date, return_date)

ATTEMPT #1
select 
  elves.elf_name,
  CASE
    WHEN vacations.return_date IS NULL THEN 'Still resting'
    ELSE vacations.return_date
from elves
join vacations on elves.elf_id = vacations.elf_id;

ERROR:
syntax error at or near "from"

CHAT:
query:
I used a case statement:
select elf_id, CASE WHEN return_date is null THEN 'Still resting' ELSE return_date END from vacations;
The error is: invalid input syntax for type date: "Still resting" What is it asking for? Why doesn't it just return a string?

response:
Great question! The error happens because your CASE statement is returning mixed data types in the same column: a string ('Still resting') and a date (return_date). In SQL, a single column must have a consistent data type, so it tries to convert everything to a date, but 'Still resting' can't be cast as a date, causing the error.
What the question is asking for is to show the return date as text, so you need to convert the date to a string before mixing it with the text 'Still resting'.

ATTEMPT:
select
  CASE
    WHEN return_date is null THEN 'Still resting'
    ELSE CAST(return_date, 'YYYY-MM-DD')
  END
from vacations;

ERROR:
syntax error at or near ","

Chat response:
're on the right track wanting to cast the date to text! The error you're seeing is because the CAST syntax in PostgreSQL doesn't take a format string like 'YYYY-MM-DD'. Instead, CAST just converts the data type without formatting.
To format a date as a string in a specific pattern, you want to use the TO_CHAR function in PostgreSQL.

This works now:
select
  CASE
    WHEN return_date is null THEN 'Still resting'
    ELSE to_char(return_date, 'YYYY-MM-DD')
  END
from vacations;

Think about how you might pick just one return date per elf—maybe the most recent, earliest, or some other rule. What aggregation or filtering technique could help you get a single return date per elf before joining or in your query?
